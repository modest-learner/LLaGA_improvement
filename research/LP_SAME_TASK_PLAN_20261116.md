# 同任务跨图 LP 研究执行方案

日期：2026-11-16。此方案取代此前以 Table 8 节点描述→节点分类为主线的执行顺序。当前只做 LP→LP；已有 Table 8 结果保留为旁支，不作为当前主张的证据，不再要求先跑 NC control。

## 1. 研究范围与可回答的问题

源图训练链接预测，冻结模型，在未参与训练的目标图进行链接预测。第一阶段在论文图中研究；第二阶段才拓展电商关系图。目标图可以提供预先规定的可见边与节点原始文本，但不能用目标测试边标签训练、选模型、调阈值、选择提示或扰动规则。用目标可见图进行消息传递是输入构建；额外用目标可见边更新模型则属于目标适应，另列。

LP 的输出标签空间始终为 {有边, 无边}。Cora、Pubmed、Arxiv 的节点主题类别不同，不意味着 LP 输出类别空间变化。区分：

- 结构分布：度数、密度、连通性、共同邻居、多跳统计。
- 文本及结构—语义对应关系：文本主题、长度、端点/邻域语义相似度。
- 评测候选分布：正负比例、随机或难负例、端点采样方式。
- 关系语义/条件分布：在相似结构与语义特征下，形成边的规律是否改变；引文→共同购买尤其需要单列。

这些因素不能仅凭两张真实图的准确率差进行因果分解。统一协议、输入干预、匹配重训、多个目标图共同提供证据。不能用 LP 实验验证“新类别名称”的影响；该问题属于以后独立的 NC→NC 研究。

RQ1：跨图 LP 使用了哪些端点语义与邻域信息？
RQ2：哪些源图条件和输入分布变化伴随稳定的迁移性能下降？
RQ3：针对已证实的失败条件，怎样在不使用目标监督的情况下改善跨图 LP？

## 2. 保留的基线与本轮核查

原主配置：Arxiv+Pubmed LP→Cora LP，HO-4、linear、lr=2e-3、SimTeG、冻结 Vicuna-7B-v1.5-16k，1 epoch，有效 batch16，仅训练 Projector。训练种子42/43/44，各3次采样推理；先对每个训练种子的推理取均值，再计算种子间样本标准差：87.1732% ± 0.6398 个百分点。这个数对应原始协议，不自动适用于新解码、清洁划分或新编码器。

原结果见 TABLE5_MULTISEED_RESULTS.md。Cora 已用于配置选择，是开发目标；重复种子不会消除选择影响。最终方法需要未参与选择的目标图。

2026-11-16 重新执行只读数据审计：results/table5/protocol_review_20261116.json。

- Cora LP test：680条，653个唯一无向对，27条重复记录，1个自连接候选，1条负例在原完整图中存在边；301个正例、379个负例。以上问题可能重叠，不能简单相减得到清洁样本量。
- 无向规范化后 LP train/test 候选无交集；存储的测试 ND 序列未发现查询边，不等于完成 HO 缓存认证。
- train/train.py 的 HO 路径读取通用预计算多跳缓存；eval/eval_pretrain.py 在 Cora/Pubmed LP 上逐查询删除当前边，局部重算。缓存究竟包含哪些边，仍须核验。当前仅删除本查询的实现与“整体移除全部测试正边”的研究协议不同。
- eval/eval_res.py 的官方 LP 评分把所有不含小写 yes 的答案当作 no。空串/解释等可能被计为负类正确。
- 先前 TABLE5_MULTISEED_RESULTS.md 的“无重复节点对”不准确，已更正；原始准确率计算没有因此改写。

这些是协议审计问题，不能直接归因为 LLaGA 的模型缺陷，也不能据此断言已确认 SimTeG 标签泄露。

## 3. 按顺序执行

### P0：锁定协议与输入审计（现在）

保存基线配置、检查点、划分/特征哈希、训练种子/推理种子与解码设置。官方复现保持原文件与评分；新研究结果放独立目录。

核验 HO 缓存生成图、训练查询边是否可见、验证/测试边是否整体隔离、对称化/自环/归一化规则、SimTeG 上游监督来源、跨图文本重复。无法核实的旧特征只作参考线。缺失来源并不等于已证实泄露。

先离线审计现有九份 LP 输出：官方 ACC；独立固定解析规则下的唯一 yes/no 有效率、条件准确率、混淆矩阵及无效案例。解析不把无 yes 自动归 no；规则在查看目标结果前固定。解释文字不自动等于无效。解析歧义要记录，不利用真实标签挑答案。

### P1：用现有 LP 权重进行低成本输入干预

先训练seed42；固定原680条测试记录、同一权重、提示、解码、端点顺序。未经清洁重训的结果仅用于探索，不作为最终严格泛化结论。官方采样结果继续作为复现参考；新诊断统一无采样贪心（do_sample=False,num_beams=1），重跑完整 HO 作新协议锚点，不能直接拿87.17%当作该锚点。

HO 每个端点表示为 [h0,h1,h2,h3,h4]，一对节点共10个图位置。所有干预对两个端点执行。

|条件|输入|作用与限制|
|LP-1 Full|每端点原始5个HO表示|同协议基准|
|LP-2 Center-only|每端点仅h0，共2个图位置|去掉多跳，但同时改变长度|
|LP-2b Center-repeat|每端点[h0,h0,h0,h0,h0]|保留10个图位置，排查长度影响；重复输入仍可能分布外|
|LP-3 Hop-mismatch|保留本端点h0，整体替换h1..4为另一个节点的多跳块|破坏中心—邻域对应关系；不是纯拓扑干预|
|LP-4 Rewired-context|保留节点文本与h0，在度数保持的重连可见图上重算h1..4|在度分布控制下改变邻域；也改变邻居语义组合|
|LP-5 Hop masks|保留前k跳，其他位置替换h0，k=1/2/3|固定位置数的尺度敏感性；避免一次穷举全部组合|
|LP-6 Endpoint text|冻结基础LLM仅读取两个端点原始文本，无图token|文本能力参考；与图组训练暴露、提示和长度不完全匹配|

先 Full、Center-only、Center-repeat、Hop-mismatch、Endpoint text 五组；再 Rewired-context 和 Hop masks。随机扰动先固定一个种子跑通，再对有意义的结果用3个预设扰动种子复核，不选最高/最低结果。

错配映射不使用标签，排除本节点与当前另一端点，保存 donor ID 与固定规则。严格版 donor 特征也必须由合法可见图生成，不能从含测试边的缓存拼入。HO含自环/多步回返，h1..4并非“纯邻居文本”；不能把错配下降直接叫作拓扑贡献。

重连只改变输入可见图，保持预测候选与原始目标标签不变，并禁止把任何评估候选对新插入可见图。它测量观测图扰动鲁棒性，不是重连后新图的真实 LP 性能。degree-preserving 算法、交换次数和拒绝条件必须保存。

LP-6只属于原始文本参考。若后续要比较文本是否能替代经源LP训练的图模型，必须另设预算可说明的源LP文本训练对照，不能把未训练文本LLM与训练Projector之间的差全部归给结构。中心嵌入匹配重训是当前优先且便宜的语义对照。

对关键组，在源图保留测试对上执行同样干预，避免把所有图都会发生的输入破坏误称为“跨图特有问题”。源/目标使用一致的候选难度与可见边规则；无法对齐时不比较差值大小。

### P2：建立清洁 LP 协议与冻结编码器线

先在 Arxiv+Pubmed→Cora 实现，不同时更换 LLM、Projector架构和编码器种类。

1. 从原始图建立独立 dataset_research 视图。规范有向/无向语义，去重、自连接候选、标签冲突和已知伪负例检查；保留映射。原复现数据不覆盖。
2. 将可见上下文边与监督查询正边分开，验证/测试正边整体从输入图移除（含反向边），随后才计算度、自环、HO。源训练正查询也必须从自己的输入图移除。可采用固定不相交的上下文/监督边划分；若用分折训练缓存，提高利用率但增加计算，须预先固定并记录所有视图。训练和推理不能一个见查询边、另一个不见。
3. 源图验证选择超参数/阈值；目标标签只用于最终离线计分。目标可见图与正查询之间的划分在方法开发前固定。目标可见边不用于模型优化。
4. 一套随机负例作为基本测试；另设度数匹配、文本高相似、二跳非边候选，规则预先固定，按负例难度分表报告。保持同一正例集、明确负正比例，排除完整已知图中真边。未观测非边不保证现实中永不相连。
5. 只先选一个可追溯、所有图共享的冻结BERT-base编码器，输入原始title+abstract、不拼节点类别；固定revision、池化、截断、归一化。重新生成所有基础与HO特征，并从头训练 LP Projector。新维度需配置支持，不能把 EMB 改成bert就直接运行。
6. 对所有研究模型用相同清洁数据、编码器和候选池比较。SimTeG/原协议与BERT/清洁协议跨两种因素，分差不能宣称是编码器的单独作用。若要研究编码器效应，必须在同一清洁划分上另训两条编码器线；不同输入维度带来的参数量差也需记录。

验收：无跨split候选重复、无query-edge输入、无保留测试边入缓存；维度/ID/中心端点映射正确；图缓存哈希可追溯；只P训练；完整HO默认分支的小样本输出与原入口一致；不使用目标标签选方案。

### P3：匹配重训，把“依赖”与“需要”分开

在同一清洁特征线上，先只训练 Full-HO 与 Center-repeat 两个 LP Projector，固定训练样本、epoch/总步数、随机种子、优化器、可训练参数范围。主超参数沿用HO/linear/lr2e-3，调整只允许依据源图验证。

|训练输入|测试Full|测试Center-repeat|
|Full|主基线|推理期删除邻域|
|Center-repeat|输入分布交叉诊断|匹配的仅中心语义基线|

Full→Full 对 Center→Center 的比较检验：同样源LP监督下，多跳输入是否带来目标收益；Full→Center 的下降只说明既有模型对输入改变敏感。交叉格不作为优化后的模型竞争结果。

先seed42筛查，关键结论补42/43/44；已完成的旧SimTeG三种子不能替代新特征/新协议重训。随机邻域训练不是第一轮必做项，仅在需要验证具体假设时增加。

加入低成本对照：端点embedding余弦、CN/AA/RA（同一合法可见图）；源图监督的端点对MLP（如对称的|xu-xv|与xu*xv）；随后源训练GraphSAGE+共享边预测头。均只在源图定阈值/超参。结构启发式和端点MLP帮助判断是否需要LLM或复杂图表示。固定常量特征的HO不能自动代表有竞争力的“纯结构模型”。

### P4：同领域多目标、多源验证

|源图LP|目标LP|用途|
|Arxiv+Pubmed|Cora|已有开发方向，换清洁协议后重建|
|Arxiv+Cora|Pubmed|新的留一图方向|
|Pubmed+Cora|Arxiv|新的留一图方向|

全部保持 LP→LP；不同方向必须独立训练，不能把已经参与训练的图当作零样本目标。先每方向seed42，Full及匹配中心基线；确认流程后补关键模型seed43/44。

多源贡献先只在Cora方向追加 Arxiv→Cora、Pubmed→Cora，与多源模型比较。既报告自然数据规模，也用固定总样本/更新预算控制训练量，注明大小源图采样权重；只有这样才能讨论多源多样性，不能把训练更多数据的收益全归给迁移机制。

为节省工作，不先铺开所有编码器×所有模板×所有源组合。现有ND结果作为模板参考，最终关键结论再用ND复核。最终确认至少加入一个未用于调参的新论文目标图；先核查其原始文本、与源图重复和边语义，确定数据版本后才执行。

### P5：按错误证据提出最小改进

每个候选保存：规范端点ID、GT、原始回答、解析状态、连续分数、度数、共同邻居、端点文本相似度、各hop差异、所属负例组、模型与视图哈希。

|观察|需要的复核|可能的改进方向（不是预设结论）|
|相似文本非边FP高|控制度数/CN/负例难度，检查端点MLP是否也失败|源图语义难负例与显式成对结构特征|
|异质邻域下Full劣于匹配中心基线|多目标与多训练种子，干预和重训结果一致|源训练的中心/多跳门控或尺度选择|
|跨图度尺度变化时性能下降|控制文本、候选池；在源/目标相同分层比较|尺度归一化或源域结构扰动训练|
|多源反而变差|控制样本/步数与图权重，排除大图支配|图平衡训练或源间一致性约束|
|对端点交换高度敏感|任务确为无向，比较(u,v)/(v,u)配对分数|对称成对表示/源训练交换增强|

分层边界在源验证集预先定义；目标标签只用于事后误差统计，不作为推理输入。观察相关性不是因果证明。方法选择仅针对最稳定的一项失败模式；加入与方法参数量/训练预算相当的简单控制，之后再补消融。

### P6：跨领域 LP（同领域完成之后）

冻结方法、提示、阈值与源图训练配方后，逐个测试 Computers、Children、Fitness(Sports)、Photo、History，不能合成一张图后把参加训练的部分叫零样本。需要核实实际边语义、原始文本和重复节点；该适配目前未实现。

论文图→电商图仍为二分类LP，但边语义可能从引用关系变成共同购买。单次迁移无法分别识别结构、文本和关系语义的独立影响。为讨论关系迁移，应补电商内部留一图及预算匹配的电商源训练参考，作为第二阶段单独研究；不把该对照偷换为论文源零样本结果。

## 4. 评分与统计

- 官方复现：原始生成ACC及历史种子统计，保留官方评分。
- 研究自由生成：严格二元解析下 Overall ACC（无效计错）、Valid rate、Conditional ACC、FP/FN及覆盖率；唯一标签解析规则预先固定。
- ROC-AUC/AP必须有连续得分。现有仅含文本的JSONL不能恢复缺失logits；把yes/no硬标签塞进AUC不构成所需排序诊断。
- 建议辅助协议为完整候选续写的 teacher-forced log-likelihood 差：s=logP(a_yes|输入)-logP(a_no|输入)。两候选共享句式，token边界与EOS策略明确；多token求完整续写概率，不硬编码单一token。只在源验证集检查措辞、长度偏差、分数方向、与生成的一致性，固定后用于所有组。它是不同的读出协议，不保证比自由生成更准确，不自动解决此前G2问题。
- 固定源阈值报告ACC/Balanced ACC，连续得分报告AUC/AP；AP依赖正例比例与候选难度，不能跨不同负例池直接比较。没有源验证前不把Cora用于选择评分器。
- 无效生成与模型执行异常分开。异常不当负类，不用0分悄悄计入排序；先修复/重跑失败项，未完整的结果标为不完整并报告覆盖率。
- 每个目标图、每种负例池分别报告；多图给等权均值及最差图。种子单位为独立训练；推理/扰动种子分开。成对比较使用同一候选集，重复对按规范无向对分组；共享节点导致的相关性仍限制置信区间解释，三张图不能支持精细的分布距离因果回归。

## 5. 本轮具体交付顺序及实现边界

1. 已完成：确认主线、检查训练/推理/评分代码、复核Cora数据、编写此计划；不启动GPU作业。
2. 接下来实现：LP专用离线输出审计与输入干预分支。沿用作者 scripts/eval.sh 和底层加载/HO构建；默认分支保持不变。现有text_only仅支持nctext，不能直接用于LP；Table8诊断脚本也不能直接换TASK=lp使用。
3. 先源验证/小样本工程检查，再现有seed42的五组初筛；同时核验源数据与缓存来源。未经核实的旧协议只作探索。
4. 构建清洁LP视图与一个冻结BERT编码器，重训Full与Center两组；评分协议在源验证固定。连续打分入口尚需实现验证，不编造现成命令。
5. 多目标/关键种子复核→最小改进→未参与调参目标确认→第二阶段跨领域。

已知旧HO双卡训练约1.7–1.8小时/次，仅供容量规划。清洁划分、特征预计算、训练视图与文本长度会改变耗时；新实现先实测小样本吞吐后估计全量，不能沿用Table8或旧推理速度承诺时间。
